# План подготовки корпуса для ML

## Цель

Преобразовать исходные документы из `docx_sources/` в проверяемый и
воспроизводимый корпус Markdown, который удобно читать, искать, разбивать на
фрагменты и использовать в RAG, дообучении и иных ML-задачах. Исходные DOCX
остаются неизменяемым первоисточником.

На момент составления плана в `docx_sources/` 39 документов (около 61 МБ), из
них 32 содержат встроенные медиа. Поэтому текст и бинарные вложения должны
экспортироваться и проверяться совместно.

## Результат и принципы

* Markdown — канонический текстовый слой; DOCX не редактируются и не удаляются.
* Каждому исходнику соответствует один Markdown-документ с устойчивым `id` и
  сохранённой связью с оригиналом.
* Иллюстрации, таблицы, ссылки, сноски и шаблоны не теряются молча: они либо
  корректно конвертированы, либо явно отмечены для ручной обработки.
* Смысловая правка отделена от технической конвертации. Это позволяет
  воспроизводить экспорт и видеть происхождение каждого изменения.
* Производные файлы для поиска и ML строятся из нормализованного Markdown, а не
  редактируются вручную.

## Целевая структура репозитория

```text
docx_sources/                 # неизменяемые первоисточники
content/
  markdown/                   # нормализованные документы (.md)
  assets/                     # извлечённые изображения, по папкам документов
  manifests/                  # метаданные документов и журнал проверки
  chunks/                     # производные фрагменты для индексации
  indexes/                    # JSONL/CSV-каталоги, создаваемые скриптом
scripts/                      # конвертация, нормализация, валидация, сборка
tests/                        # регрессионные проверки разметки (по необходимости)
docs/
  CONTRIBUTING.md             # правила ручной разметки и именования
```

Создавать эти каталоги следует вместе с реализацией соответствующего этапа,
чтобы не появлялись пустые или неиспользуемые артефакты.

## Очерёдность первой итерации

1. Утвердить лицензию, набор выходных форматов и словарь `document_type`/тегов.
2. Добавить манифест и скрипт инвентаризации.
3. Установить и зафиксировать конвертер, затем сделать пробный экспорт 3–5
   репрезентативных файлов: обычной главы, документа с таблицами, шаблона,
   «Врезки» и документа с изображениями.
4. По результатам пробы зафиксировать правила нормализации и автоматизировать
   их.
5. Конвертировать весь корпус, провести вычитку по приоритету, затем построить
   JSONL и чанки.

## Что не входит в первый выпуск

* изменение авторского содержания, фактов или стиля;
* генерация новых игровых материалов моделью;
* выбор конкретной векторной БД или модели эмбеддингов — корпус должен быть
  независим от них;
* OCR – не нужен, однако требуется составление описаний для тех изображений, что пока не распознаны.
