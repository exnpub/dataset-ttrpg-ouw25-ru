# Руководство по внесению изменений (CONTRIBUTING)

Этот документ описывает правила ручного редактирования и расширения корпуса «Укрытое море».

## Принципы

1. **Каноничность Markdown** — все правки вносятся в `content/markdown/`, а не в `imported/`.
   Файлы в `imported/` автоматически пересчитываются при пересборке, поэтому правки там теряются.

2. **Разделение слоёв** — смешивание технической конвертации с содержательной правкой
   запрещено. Это затрудняет отслеживание источника изменений.

3. **Метаданные жёсткие** — YAML front matter (первые 20 строк) редактируется с осторожностью.
   ID, источники и статусы должны оставаться стабильными.

4. **Воспроизводимость** — любые изменения в индексы должны быть результатом пересборки
   скриптом, а не ручного редактирования JSON.

## Как редактировать документы

### 1. Исправление опечаток и стиля

```markdown
# ДО
Благославленный прилив был открыт в 1920-х годах.

# ПОСЛЕ
Благословенный прилив был открыт в 1920-х годах.
```

**Правила:**

- Исправляйте опечатки в русском тексте и игровых терминах
- Не меняйте авторское содержание или фактичность
- Сохраняйте иронию и тон оригинала

### 2. Уточнение таблиц

Если таблица некорректно конвертирована из DOCX:

```markdown
# ДО (неправильно сконвертированная)
| Товар | Цена | Статус |
| --- | --- |
| Гвозди | 50 ф. | ✓ |

# ПОСЛЕ (исправлено)
| Товар | Цена | Статус |
| --- | --- | --- |
| Гвозди | 50 ф. | ✓ |
```

### 3. Добавление описаний к изображениям

Если изображение имеет `alt: "Изображение — требуется описание"`:

```markdown
# ДО
![Изображение — требуется описание](../assets/ouw25-3-1-narody-morya/image-001.png)

# ПОСЛЕ
![Народы Укрытого моря: портреты пяти основных рас](../assets/ouw25-3-1-narody-morya/image-001.png)

*Рис. 1: Образцы характерных черт апокрифов, мээнов, геноцидников, ватников и ондатр 
из справочника «Морские нации» (1925 г.)*
```

**Правила для alt-текстов:**

- Содержательный, конкретный, не "Изображение 1"
- Без кавычек (исключение: названия в кавычках внутри)
- Для декоративных изображений можно оставить пусто: `alt=""`
- Для скриншотов интерфейса: описать функцию, а не пиксели

### 4. Исправление ссылок

Если ссылка битая или неправильно оформлена:

```markdown
# ДО (draft-формат из DOCX)
<https://example.com/some-page>
<[нажмите сюда](https://example.com)>

# ПОСЛЕ (стандартный Markdown)
[Пример](https://example.com/some-page)
[нажмите сюда](https://example.com)
```

### 5. Расширение сокращений

Игровые термины должны быть расшифрованы при первом упоминании:

```markdown
# ДО
ДД — главный источник власти.

# ПОСЛЕ
ДД (Девять Дел) — главный источник власти в коалиции.
```

## Обновление метаданных

### Изменение статуса документа

```yaml
---
status: "needs_review"  # БЫЛО
status: "reviewed"       # СТАЛО
---
```

**Возможные статусы:**

- `needs_review` — требует ручной проверки
- `reviewed` — проверен, готов к использованию в ML
- `draft` — не публикуется (редко используется)

### Добавление тегов

```yaml
---
tags: []  # БЫЛО
tags: ["морское-право", "торговля", "персонажи"]  # СТАЛО
---
```

**Рекомендуемые теги:**

- `персонажи` — NPC, примеры ведения
- `таблицы` — случайные события, товары, генераторы
- `правила` — механики, разъяснения
- `морское-право` — договоры, конфликты, спорные случаи
- `порты` — описания мест
- `экономика` — торговля, спекуляция, цены

## Перестройка индексов

После любого редактирования в `content/markdown/` обязательно пересчитайте индексы:

```bash
# Из корня проекта
python3 scripts/build_indexes.py
```

Это обновит:

- `content/indexes/documents.jsonl` — метаданные и полные тексты
- `content/chunks/chunks.jsonl` — семантические фрагменты
- Хеши `text_sha256` для проверки целостности

## Процесс ревью при внесении изменений

1. **Редактируйте только** `content/markdown/XXX.md`
2. **Проверьте** изменения локально в редакторе Markdown
3. **Запустите** валидацию:
   ```bash
   python3 scripts/validate_corpus.py
   ```
4. **Пересчитайте индексы:**
   ```bash
   python3 scripts/build_indexes.py
   ```
5. **Сверьте с оригиналом** в `docx_sources/` если сомневаетесь
6. **Зафиксируйте изменение** в git:
   ```bash
   git add content/markdown/XXX.md content/indexes/ content/chunks/
   git commit -m "docs: исправление опечатки в XXX"
   ```

## Добавление новых разделов (редко)

Если правообладатель добавляет новые материалы:

1. **Поместите DOCX** в `docx_sources/`
2. **Запустите первичную конвертацию:**
   ```bash
   python3 scripts/build_corpus.py --refresh-markdown
   ```
   (Флаг `--refresh-markdown` только в этом случае!)
3. **Отредактируйте** новый Markdown в `content/markdown/`
4. **Пересчитайте индексы** и валидируйте

**Важно:** этот процесс требует тестирования, чтобы не повредить существующие документы.

## Форматирование кода и комментариев

### Код и шаблоны

Код в документах оформляется стандартным Markdown:

```markdown
\`\`\`python
def check_risk():
    return roll(2, 6) < captain_skill
\`\`\`
```

### Комментарии редактора

Для внутренних заметок используйте HTML-комментарии (исключаются из ML-индексов):

```markdown
<!-- TODO: найти оригинальную таблицу в DOCX и уточнить цены -->
| Товар | Цена |
| --- | --- |
| ... | ... |
```

## Частые ошибки

❌ **Неправильно:**
- Редактировать `imported/XXX.md` (теряется при пересборке)
- Напрямую менять `documents.jsonl` или `chunks.jsonl`
- Менять ID или `source_path` без обновления манифеста
- Смешивать содержательные правки с техническими в одном коммите

✅ **Правильно:**
- Редактировать `content/markdown/XXX.md`
- Пересчитать индексы скриптом после правок
- Обновлять `content/manifests/documents.json` при серьёзных изменениях
- Разделить комменты: "docs: исправление" vs "build: перестройка индексов"

## Спорные ситуации

### Что если я не уверен в исправлении?

Добавьте комментарий в `content/manifests/issues.json`:

```json
{
  "document_id": "ouw25-3-4-personalii-i-kharakternye-tipy",
  "category": "clarification_needed",
  "severity": "review",
  "status": "open",
  "message": "Уточнить, в каком году умер персонаж Б. Вместилище — в тексте противоречие."
}
```

### Что если нужна история изменений?

Используйте `git log`:

```bash
git log -p content/markdown/ouw25-3-4-personalii-i-kharakternye-tipy.md
```
